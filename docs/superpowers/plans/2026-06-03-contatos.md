# Contatos — Base unificada + foto + classificação (Fase A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transformar a "Base AMMOC" numa página **Contatos** unificada (conversas pessoais + cidadãos do Canal), com foto (manual/avatar/iniciais), e classificação por **categorias livres** (múltiplas por contato + filtro).

**Architecture:** Frontend Next.js lê `conversations` + `canal_conversations` via Supabase client (RLS-scoped) e dedupa por número; novas tabelas `contact_categories`/`contact_category_assignments`/`contact_photos` (RLS: leitura autenticada, escrita admin/supervisor) geridas pelo client; foto manual sobe pro Storage. Sem novo módulo de API.

**Tech Stack:** Next.js 15 + Supabase (Postgres + Storage, RLS) + TypeScript.

**Spec:** [docs/superpowers/specs/2026-06-03-contatos-classificacao-design.md](../specs/2026-06-03-contatos-classificacao-design.md)

**Padrões a reaproveitar:** `apps/web/src/app/(app)/base/page.tsx` (lista atual + dedupe), `apps/web/src/app/(app)/meu-numero/page.tsx` (fetch lazy de avatar via `GET /api/whatsapp/avatar?number=`), `apps/web/src/app/(app)/configuracoes/setores/page.tsx` (modal de gestão + chips), `apps/web/src/components/layout/Sidebar.tsx`.

### Task 3: Página Contatos — unificar fontes + foto + categorias

**Files:** reescrever `apps/web/src/app/(app)/contatos/page.tsx`.

- [ ] **Step 1: Carregamento unificado + metadados**

Client component. Estado e carregamento (via `createClient()` do `@/lib/supabase/client`):
- Buscar em paralelo:
  - `conversations`: `.select('contact_name, contact_number, municipality, status, last_message_at').neq('status','nao_salva')` → origem `'pessoal'`.
  - `canal_conversations`: `.select('wa_contact_name, wa_contact_number, status, last_message_at')` → mapear para `{ contact_name: wa_contact_name, contact_number: wa_contact_number, municipality: null, status, last_message_at }`, origem `'canal'`.
  - `contact_categories`: `.select('id, name, color').order('name')`.
  - `contact_category_assignments`: `.select('contact_number, category_id')`.
  - `contact_photos`: `.select('contact_number, photo_url')`.
- **Normalizar número** (só dígitos) como chave; **dedupe**: manter a entrada com `last_message_at` mais recente; se o mesmo número aparece em ambas as fontes, marcar origem `'ambos'`.
- Montar, por contato: `{ number, name, municipality, status, last_message_at, origem, categoryIds: string[], photoUrl?: string }` (categoryIds via mapa número→[category_id]; photoUrl via mapa número→url).
- **Avatar automático (Evolution)**: para contatos SEM `photoUrl`, fazer fetch lazy de `GET /api/whatsapp/avatar?number=<digits>` (com token via `supabase.auth.getSession()`, header Bearer; usar `getApiBase()` de `@/lib/api-base`) dos primeiros ~30 visíveis, guardando num mapa `avatars[number]`. (Mesmo padrão de `meu-numero/page.tsx`.)

- [ ] **Step 2: Foto, render do card e filtros**

- **Foto exibida**: `photoUrl` (manual) → senão `avatars[number]` (Evolution) → senão **iniciais coloridas** (cor derivada do nome, como em meu-numero).
- **Lista**: busca (nome/número/município) + **chips de filtro por categoria** (`Todas` + uma por categoria com sua cor; clicar filtra; um contato passa se tiver a categoria selecionada). Opcional: filtro por origem.
- **Card** de contato: foto, nome, número formatado (reusar o `fmtPhone` existente), município (se houver), badge de origem (pessoal/canal/ambos), **chips das categorias do contato** (cor) cada um com ✕ para remover, um botão "＋ categoria" abrindo um menu/select das categorias existentes para atribuir, e um botão **📷** para enviar foto.
- **Atribuir/remover categoria** (admin/supervisor): `supabase.from('contact_category_assignments').insert({contact_number, category_id})` / `.delete().eq(...).eq(...)`; recarregar mapa. (A RLS bloqueia não-admins; esconder os controles para quem não é admin/supervisor — checar o papel do usuário logado, ex.: `users.role`.)
- **Upload de foto**: `<input type=file accept="image/*">` → `supabase.storage.from('wa-media').upload('contacts/<number>-<ts>.<ext>', file, {upsert:true})` → `getPublicUrl` → `supabase.from('contact_photos').upsert({contact_number, photo_url})` → atualizar estado.

- [ ] **Step 3: Gerenciar categorias (admin/supervisor)**

- Botão "Categorias" abre um modal (estilo do modal de setores): lista as categorias (nome + cor + ✕ excluir) e um form para criar (nome + input `type=color`) → `supabase.from('contact_categories').insert({name, color})` / `.delete().eq('id', id)`; recarregar.
- Mostrar os controles de gestão (criar/excluir categoria, atribuir, foto) só se o usuário for admin/supervisor (ler o papel via `supabase.from('users').select('role').eq('id', uid)` ou da sessão).
